# 新UI全画面適用・完了計画

最終更新日: 2026-08-13

## 目的

工程11で完了した共通ボタン体系だけでなく、共通のPCサイドNAV、モバイルドロワー、ページヘッダー、本文シェル、見出し、状態表示までを「新UI」として全画面へ適用する。

## 判定基準

- **適用済み**: 共通シェルまたは意図した独立シェル、共通操作体系、主要状態表示が揃っている。
- **部分適用**: 共通ボタン等はあるが、旧ヘッダー／旧NAVが残る、または `app-shell` がなくPCサイド配置が成立しない。
- **独立UI維持**: ログイン、エラー、長文閲覧など、共通NAVを置かないこと自体が仕様。ただし色、フォーム、ボタン、状態表示は共通規則へ合わせる。

## 実装工程

### 工程13-0: メンバー管理メニュー遷移修正

**状態: 完了**

- モバイルドロワー内の通常リンク選択時に、開閉処理と競合せず明示的にURLへ遷移する。
- Ctrl／Command／Shiftクリックなどの標準操作は維持する。
- `member_settings` のURL、管理者権限、現在位置表示を回帰テストする。

完了条件: メンバー管理リンクが展開だけで停止せず、一覧画面へ遷移する契約をテストで固定する。

### 工程13-1: 管理設定シェルの完成

**状態: 完了**

対象: `dashboard` のメンバー関連4画面。

- 外側を `app-shell`、本文を `app-shell-content` へ統一する。
- 検索、一覧、登録、ID一括、部署管理の既存フォーム・AJAX・権限を維持する。
- PCサイドNAV、モバイルドロワー、タブ、横長一覧を確認する。

### 工程13-2: Performance全画面移行

**状態: 完了**

対象: 旧ヘッダー／旧NAVを持つPerformance画面群。

- 手書きの `header`／`nav_items` 表示を共通 `app_navigation.html` へ移行する。
- 管理者表示、本人表示、閲覧専用表示で遷移先と表示項目を維持する。
- 日付詳細、AJAX、ページング、編集・削除、あと一歩ノート固有デザインを維持する。
- 画面数が多いため「管理者CRUD」「個人実績・履歴」「あと一歩ノート」の3コミットに分割する。

管理者CRUDは全体エントリー、過去実績入力、戻り・増額、日次編集、決済編集の5画面を共通シェルへ移行済み。

個人実績・履歴は全体の過去実績、個人ダッシュボード、個人履歴の3画面を共通シェルへ移行済み。管理者・本人・閲覧専用の導線と分析対象パラメータは維持する。

あと一歩ノートは固有のヒーロー、絞り込み、AJAX結果更新、FABを維持したまま共通シェルへ移行済み。あわせて共通NAVのモバイルハンバーガーを新 `ui-icon-button` へ統一した。

### 工程13-3: DairyMetrics・Mail移行

**状態: 完了**

対象: `dairymetrics/metrics_v2.html`、`dairymetrics/metrics_report.html`、`mail/settings.html`。

- 旧NAVを共通NAVへ移行し、権限別リンクと選択中部署・メンバーを維持する。
- グラフ、比較、モーダル、エクスポート、Gmail設定の機能契約を変更しない。
- 保存中、通信失敗、空状態、機密値非再表示を再検証する。
- 旧 `.btn-inline` のモバイルハンバーガーを共通 `ui-icon-button` へ置き換える。

DairyMetricsの分析・振り返りレポートを共通シェルへ移行し、管理者・本人・閲覧専用の権限別リンクと部署・メンバー引き継ぎを維持した。MailのGmail連携は既に共通シェル化済みの統合設定画面を正とし、旧設定テンプレートも共通シェルへ揃えた。

追加改善として、実績管理の部署選択をページヘッダーのタイトルとモバイルメニューの間へ移し、「表示」ボタンを廃止した。選択時は本文をAJAXで差し替え、URL履歴、戻る操作、通信失敗時の復元、グラフ再初期化を維持する。

### 工程13-4: 概ね適用済み画面と独立UIの仕上げ

**状態: 完了**

対象: `targets`、`reports`、`talks`、`testimony`、`monthly_guide`、`mosaic`、`accounts`、エラー画面。

- partial・モーダル・削除確認・検索結果・履歴詳細を含めて、見出し、空、成功、失敗、読み込み中を監査する。
- インラインCSSは動的値だけを残し、固定値は共通またはアプリCSSへ移す。
- 固有UIを共通カードへ無理に置換せず、共通トークンと操作規則だけを揃える。
- `mosaic` 等の独自ヘッダーに残るモバイルハンバーガーも共通 `ui-icon-button` へ統一する。

Mosaicは全7画面の親を正式な `app-shell`／`app-shell-content` 構造へ修正し、PCサイドNAV、モバイルドロワー、共通 `ui-icon-button` を成立させた。接客入力、一覧、マスター管理、権限別リンク、送信ロックは維持する。

Targets・Reports・Talks・Testimony・各ログイン画面に残っていた固定インラインCSSを共通またはアプリCSSへ移した。お気に入り・リアクションの色、タグ折りたたみの初期表示など、状態やデータに応じて動的に決まる指定だけを残した。対象7アプリ157テストと、旧ハンバーガークラス・固定インラインCSSの機械監査を通過した。

次は工程13-5で、全画面・権限・PC／モバイル・操作・静的検査を横断し、新UI全画面適用の完成判定を行う。

### 工程13-5: 横断監査・完成判定

**状態: ローカル完了（確認画像の利用者確認待ち）**

- 名前付き画面URL、権限、PC／モバイル、キーボード、戻る、フォーム、AJAX、二重送信防止を確認する。
- 旧 `topbar`／手書きNAVが意図せず残っていないことを機械検査する。
- `dashboard-drawer-toggle` に旧 `.btn-inline` が残っていないこと、全画面で共通 `ui-icon-button` が使われることを機械検査する。
- 残る `.btn-inline` と固有クラスは、ページング、ドロワートグル等の理由を台帳へ記録する。
- 全テスト、Django check、migration、BOM、JavaScript構文、EOF、差分監査を実行する。
- チャットから確認できるPC／モバイル固定画像を更新し、利用者確認後にPUSH工程へ渡す。

本番テンプレート86件、URLパターン191件、名前付きURL178件を横断監査した。旧上部メニュー生成コードを削除し、共通シェル35件とドロワーボタン3系統、残る `btn-inline` 57件の用途を確認した。全405テストと静的検査、ChromeによるPC幅1440px／モバイル幅390pxの実画面確認が成功した。詳細は `UI_COMPLETION_AUDIT_2026-08-13.md` を参照する。

## 工程共通ルール

- 1工程ずつ実装し、対象テスト・レビュー・コミット後に次へ進む。
- URL、権限、集計、保存、AJAX、機密情報非表示を外観変更のために変更しない。
- PUSH、PR、公開は実装工程と分離する。
- 変更が10ファイルまたは500行を超える前に工程を分割する。
