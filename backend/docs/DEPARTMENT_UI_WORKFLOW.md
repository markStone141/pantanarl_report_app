# UIで部署を追加する手順とコード上の依存

## 調査結果

| 対象 | 部署追加時のコード修正 | 理由 |
| --- | --- | --- |
| 部署管理 `/dashboard/departments/` | 不要 | `DepartmentForm` と `department_settings` が名称・コード・表示設定を保存する |
| メンバー所属・デフォルト報告者 | 不要 | 登録済み部署をDBから選択する |
| 目標指標 | 不要 | 部署管理UIで件数・金額などの指標を追加できる |
| モデル・マイグレーション・初期化コマンド | 不要 | 部署コードは自由入力。新部署を初期データに追加しない |
| 報告入力入口・フォーム | 今回汎用化 | 既存コードは4部署の固定ルートのみを入口にしていた |
| 保存報告一覧の部署フィルタ | 今回汎用化 | 固定コードリストを除き、登録済み部署を参照する |
| 目標設定の部署一覧 | 今回汎用化 | 固定リストからDB参照へ変更し、ページ表示による部署自動作成も廃止する |
| 保存済み報告の閲覧・編集 | 不要 | 部署の外部キーで既存報告を参照する。部署を削除・改名しない |

今後の通常の部署追加はUIだけで行える。WV固有のCS・難民支援など、新しい集計仕様を追加する場合は別途コード対応が必要。
管理画面のメール本文作成にもUIで追加した部署が独立した欄として表示される。既存部署の見出し・順序を維持し、新部署を後ろに追加する。

## Style1の入口をUN関西へ置き換える

1. 管理者で「部署管理」を開き、表示名 `UN関西`、未使用の部署コード（例: `UN_KANSAI`）で追加する。
2. 「提出状況・報告入力に表示」をオンにする。目標設定・履歴の表示は運用に応じて選ぶ。
3. 必要なメンバーをUN関西に所属させ、必要ならデフォルト報告者を設定する。
4. 目標を使用する場合はUN関西を選択して `count`（件数・件）、`amount`（金額・円）などの指標をUIで追加する。
5. Style1の「提出状況・報告入力に表示」をオフにする。Style1の部署は削除せず、名称・コードも変更しない。

UN関西の入口は `/reports/department/UN_KANSAI/` に表示される。未登録部署へのアクセスでは部署を作成しない。
Style1の過去報告・明細は保存報告一覧に残り、既存の編集URLで編集できる。入力入口の非表示と履歴の保存は独立している。

## UNと同じ分析・振り返りを使う

- UN関西の部署コードは `UN_KANSAI` とする。`UN` および `UN_` で始まる部署コードは、UNと同じ安定スコアを含む分析・振り返り指標を使う。
- 分析・振り返り画面で部署を選ぶと、その部署に所属するメンバーと、その部署に登録された実績を表示する。両部署に所属するメンバーも、部署ごとの実績・個人目標が分かれている。
- 月目標・路程目標は部署ごとの指標に個別の値を設定する。個人の月／路程目標も部署ごとに保存される。
- メール本文作成にはUN関西の専用欄が表示され、メンバー別実績、月／路程目標と進捗を独立して表示する。既存の「UN全体」欄（UNとWVの合計）には関西を混ぜない。
- 部署を新規作成しただけではメンバーや目標はコピーしない。所属・指標・目標をUIで設定する。
