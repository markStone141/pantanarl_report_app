# テストスイート高速化・重複整理

実施日: 2026-08-13

## 目的

業務仕様・権限・回帰契約を減らさず、標準の `python manage.py test` の待ち時間と、値だけが異なる類似テストの保守負担を減らす。

## 変更

- `manage.py test` の既定設定を `config.settings.test` とした。通常コマンドは従来どおり `config.settings.local` を使用する。
- テスト設定だけ `MD5PasswordHasher` を使用する。通常設定の既定ハッシャーは `pbkdf2_sha256` のまま変更しない。
- ログイン、匿名アクセス、Dashboard NAV、Reports旧リンク、Talks管理権限、DairyMetrics期間選択の類似ケースを `subTest` へ統合した。
- 統合前後で各URL、利用者種別、認証方式、期待遷移、権限、表示契約のケースは維持した。
- テスト設定が高速ハッシャーを使うことを回帰テストで固定した。

## 結果

| 項目 | 変更前 | 変更後 |
|---|---:|---:|
| 検出テスト数 | 405 | 396 |
| Django表示の実行時間 | 344.483秒 | 28.516秒 |
| コマンド全体の経過時間 | 約345秒 | 45.20秒 |
| 完全一致するテスト本文 | 0グループ | 0グループ |

コマンド全体の経過時間は約87%短縮した。テストDB作成・破棄やOneDrive上のファイル処理を含むため、Djangoが表示するテスト本体時間より長い。

## 検証

- 統合対象75テスト: 成功
- 全396テスト: 成功
- 通常ハッシャー: `pbkdf2_sha256`
- テスト用ハッシャー: `md5`
- Django system check: 成功
- migration差分: なし
- Python構文、BOM、EOF、Git差分: 成功

## 今後の方針

- テスト数だけを目的に業務ケースを削除しない。
- 同じ準備・同じ操作・同じアサーションで入力値だけが異なる場合は、表形式と `subTest` を優先する。
- 共通シェルの静的契約は `audit_ui_shells.py`、画面ごとの権限・現在位置・業務リンクはアプリテストで分担する。
- さらに短縮する場合は、変更アプリの対象テストを先に実行し、全体テストを工程終了時に1回実行する。
