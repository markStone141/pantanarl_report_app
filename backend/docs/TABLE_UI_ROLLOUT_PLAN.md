# テーブル・状態バッジUI再設計計画

最終更新日: 2026-08-13

## 目的

総合管理ページの目標管理テーブルを基準に、主要画面のテーブルと「未提出」等の状態バッジを新UIへ統一する。

## 設計原則

- 見出し、主要値、補足値、状態、操作の視覚的優先順位を明確にする。
- 数値と金額は右揃え、単位と桁区切りを統一する。
- 操作列は共通ボタンとアイコン操作に限定し、重要値と視覚的に分離する。
- モバイルは横スクロール依存を減らし、行をカード化して項目名と値を対で表示する。
- 空状態は表内の単なる `colspan` 文言ではなく、共通の空状態表示を使う。

## 状態バッジ体系

- `neutral`: 未設定、対象外、情報なし。
- `info`: 予定、準備中、確認中。
- `success`: 提出済み、完了、達成。
- `warning`: 未提出、未入力、要確認。
- `danger`: 期限超過、失敗、無効、危険な状態。

色だけで区別せず、文言、アイコンまたは輪郭の違いを併用する。すべてのバッジでコントラストと狭幅表示を確認する。

## 実装工程

### 工程14-1: 総合管理を基準デザインにする

- 第1単位完了: 報告入力／総合管理で対象月・現在路程・日本語状態を共通パネル化し、目標進捗を「指標名・実績・目標・達成率」の部署カードへ再設計した。モバイルは横スクロール不要。
- 提出状況一覧を部署・担当者・提出時刻・ステータスの4項目へ整理し、件数・内訳・金額・修正を展開領域へ移した。部門別実績も金額・件数を主値にした部署カードへ更新済み。
- 目標管理の月目標と路程目標を、同じ情報構造の新テーブルへ再設計する。
- 部署、目標、実績、残り、達成率の優先順位を整理する。
- 提出状況一覧の「未提出」「提出済み」等を新状態バッジへ移行する。
- PC・モバイルの基準画面として固定画像とテストを用意する。

### 工程14-2: 管理・目標系テーブルへ展開

- 作成済み月／路程目標の履歴詳細を、実績を主値にした指標カードへ変更済み。
- 月目標／路程目標の作成フォームを、期間設定パネルと部署別入力カードの共通UIへ変更済み。モバイルは1列化し、横スクロール不要。
- 部署管理、メンバー管理、ID一括管理、月目標、路程目標、履歴詳細を対象にする。
- 「未設定」「予定」「進行中」「完了」「達成」「未達」等の表示を共通バッジに統一する。

### 工程14-3: 日常入力・実績・履歴テーブルへ展開

- 全体／個人の「過去の実績」目標達成カードを、実績・目標・達成率・通常／補正内訳の共通構造へ変更済み。
- `reports`、`performance`、`dairymetrics`、`mail`、`talks`、`testimony` の主要一覧を台帳化する。
- テーブルが適切でない画面は、カード一覧や詳細行へ変更する。
- AJAX差し替え、ページング、ソート、編集・削除導線を維持する。

### 工程14-4: 横断監査・完成判定

- 全テーブルと状態文言を機械棚卸し、旧 `.badge` の用途と残存理由を台帳に記録する。
- キーボード、スクリーンリーダー用文言、色覚非依存、PC・モバイル、空・読み込み・失敗状態を確認する。
- 全テストと視覚確認の完了後にPUSH工程へ渡す。

## 工程共通ルール

- 集計値、状態判定、権限、URL、AJAXのレスポンス契約は変更しない。
- 共通CSSを優先し、画面ごとに別名の同義クラスを増やさない。
- 1単位ずつ実装、対象テスト、視覚確認、レビュー、コミットを行う。
